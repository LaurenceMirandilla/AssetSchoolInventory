Companion files: screens.html (page blueprints) and frontend-design.md (the reasoning and the Razor snippets).

Colour

Green is the institutional colour and carries one meaning only: this is an action you can take, plus "good" in a status. It is never decoration. Greys carry structure, and the four accent hues carry status — amber waiting, blue in-hand, red wrong, purple in-motion, grey ended.

Type

System font stack, five sizes, three weights (500/600/700). Numbers in tables use tabular figures via .sab-cell-num so columns of costs and counts line up.

Icons

One inline SVG sprite (Views/Shared/_Icons.cshtml), no icon font, no CDN. They inherit currentColor and are aria-hidden, because every icon in this app sits beside a text label. Icon-only buttons put the label in aria-label on the button.

Status pills

A pill is the enum, spelled the way the enum spells it. The class is built in the view as status-@Value.ToString().ToLowerInvariant(), so a new enum member needs a new rule in site.css — otherwise it renders as an unstyled pill, which is the intended fail-safe (readable, just plain).

Buttons

One primary action per screen — the thing the page exists for. Everything else is secondary or a link. Destructive actions are red and confirmed via data-confirm; red alone has never stopped anyone.

Page header — .sab-page-header

Title, one line of context, actions right. The subtitle answers "how many / whose / as of when", never repeats the title.

Stat tiles — .sab-stats / .sab-stat

On a list page each tile is a link that filters the list below it, and the active one is marked with .is-active — replacing today's inline border border-2. A tile that filters nothing should not be a link.

Filter bar & chips — .sab-filters / .sab-chips

A plain GET form: the URL holds the filter state, so a filtered list is bookmarkable and the back button behaves. Chips below show what is currently narrowing the result and remove it in one click — without them, two rows out of 248 is a mystery.

Data table — .sab-table-card

Count, rows and pager inside one card. Sortable headers are links (.sab-sort), so sorting works without JS and a sorted view can be pasted into an email. Rows carry data-label so they can restack as cards under 760px.

Forms — .sab-form, .sab-context

One column, max 720px, grouped in fieldsets. Any form that acts on something opens with a read-only .sab-context block naming what it is acting on — deciding a request with the asset's details one page back is how the wrong unit gets issued. Validation stays with jQuery unobtrusive, which is already wired up.

Flash messages & bars
